# 色ずれ（スペクトラム） for YMM4

[![License](https://img.shields.io/badge/license-MIT-blue.svg)](#)
[![.NET](https://img.shields.io/badge/.NET-10.0-purple.svg)](#)
[![Release](https://img.shields.io/github/v/release/routersys/YMM4-SpectrumColorShift.svg)](https://github.com/routersys/YMM4-SpectrumColorShift/releases)

---

YukkuriMovieMaker4（YMM4）上で動作する、映像の色を400nmから700nmの波長に分け、波長ごとに異なる量だけずらして足し合わせ、虹色の縁として描画する映像エフェクトプラグインです。
履歴フレーム、参照画像、学習済みモデルを使わず、入力された一枚の映像だけを処理します。
色のずれ方は設定と画素の位置から決定論的に決まり、同じ設定では常に同じ絵になります。
距離、角度、中心X、中心Y、強さ、基準波長の6項目はアニメーションに対応しています。

## 概要

本プラグインはYMM4の映像エフェクトとして動作し、エフェクトの種類一覧では「色ずれ（スペクトラム）」として表示されます。カテゴリは加工です。

波長は光の色を表す値で、短いほど青く、長いほど赤くなります。400nmから700nmまでの波長の並びが、スペクトルです。映像の各画素について、波長ごとにずらした位置の色を読み取り、波長ごとの重みを掛けて足し合わせた色で描き直します。ずらす量は波長と「基準波長」との違いから決め、「分散」で回折格子とプリズムのどちらの決め方にするかを選びます。

重みは、人の目が各波長の光をどんな色として感じるかを表す等色関数から求めます。等色関数の計算は、Wyman, Sloan and Shirleyの論文「Simple Analytic Approximations to the CIE XYZ Color Matching Functions」（Journal of Computer Graphics Techniques、2013年）に基づきます。

結果は設定と画素の位置だけから決まります。時間値と乱数は使いません。同じフレームは何度描いても同じ結果になります。

処理はDirect2Dのカスタムピクセルシェーダーが行います。波長ごとの重みとずらし量の表はCPUで求め、シェーダーの定数として渡します。CPUへの画素の読み戻しは行いません。

このエフェクトはAviUtl向けのEXO出力には対応していません。

## インストール方法

1. [Releases](https://github.com/routersys/YMM4-SpectrumColorShift/releases/latest)ページから最新のプラグインファイル（`.ymme`）をダウンロードしてください。
2. YMM4が起動していないことを確認し、ダウンロードしたファイルを実行してインストールします。
3. YMM4を起動し、タイムライン上のアイテムに映像エフェクトを追加します。
4. 映像エフェクトの種類として「色ずれ（スペクトラム）」を選択してください。

## 主な機能

### 1. 距離と方式

「距離」は、色が動く最大の大きさです。400nmと700nmの両端のうち、動きが大きいほうの端が、ちょうど「距離」だけ動きます。基準波長は、位置が動かない色の波長です。基準波長より波長の短い側と長い側は、反対の向きへ動きます。0pxでは映像をそのまま通し、負の値にすると向きが逆になります。

「方式」は、ずらす向きの決め方です。

- 直線: 「角度」で決めた一方向へずらします。0°が右、90°が下です。「距離」は映像全体で同じです。
- 放射: 中心から外へ向かってずらします。レンズの色収差に近い見た目になります。ずれは中心からの距離に比例します。「距離」が、中心から最も遠い点までの距離の半分以下のときは、その点で「距離」と等しくなります。青い側は外へ、赤い側は内へずれます。
- 回転: 中心を軸に、波長ごとに異なる角度で回します。中心から最も遠い点が円弧に沿って動く距離が「距離」と等しくなります。青い側は時計回りに、赤い側は反時計回りに回ります。

次の画像は、左上が元の映像で、ほかの3つは「距離」を24pxにして「方式」だけを変えた例です。ほかの項目は既定値です。

![Image](https://github.com/routersys/YMM4-SpectrumColorShift/blob/main/docs/SpectrumColorShift-Modes.png)

放射と回転の中心は、画面の中心ではなく、このエフェクトに入る映像の中心です。「中心X」と「中心Y」で、この中心を動かせます。「角度」は方式が直線のときだけ、「中心X」と「中心Y」は方式が放射か回転のときだけ表示されます。

### 2. 波長ごとの重み

各波長の重みは、等色関数から求めた、その波長の光の赤、緑、青の成分です。負になる成分は0にします。さらに、赤、緑、青のそれぞれで、すべての波長の重みを足すと1になるよう揃えます。このため、「距離」が0pxのときと、色が一様な領域では、映像の色は変わりません。

### 3. 基準波長

「基準波長」は、位置が動かない色の波長で、範囲は400nmから700nmまでです。450nm付近が青、550nm付近が緑、650nm付近が赤です。450nmにすると青が動かず、緑と赤が青から離れる向きへ動きます。

### 4. 分散

「分散」は、波長ごとの動きの大きさをどう決めるかを選ぶ項目です。

- 回折格子: 回折格子は、細かい溝で光を波長ごとに分ける板です。この方式では、動きが、波長と基準波長との差に比例し、スペクトルが均等に広がります。
- プリズム: プリズムは、光を屈折させて波長ごとに分けるガラスなどの透明な塊です。この方式では、動きが、波長の2乗の逆数と基準波長の2乗の逆数との差に比例し、青い側が大きく広がり、赤い側は狭くなります。この式は、ガラスの屈折率が波長によって変わる様子を表すコーシーの分散式の、主な項と同じ形です。

### 5. ステップ数

「ステップ数」は、400nmから700nmまでを等間隔に分ける波長の数です。画素ごとに、この数に応じた回数だけ映像を読み取ります。「距離」が大きいと、ステップ数が少ないときに、色ごとの映像が離れて段のように見えます。回折格子では、「距離」の2倍を「ステップ数」から1を引いた数で割った値が、隣り合う波長の動きの差の上限です。プリズムでは、青い側の差がこの値より大きくなります。この差が小さいほど、色はなめらかにつながります。ステップ数を増やすほど処理は重くなります。

### 6. 強さと映像の外形

「強さ」は、色をずらした映像を元の映像に混ぜる割合です。0%にすると元の映像のままになります。

色をずらした映像は、元の外形の外へはみ出します。直線では、「角度」で決めた向きに沿って「距離」を横の長さと縦の長さに分け、その長さをそれぞれ切り上げて2pxを足した幅だけ、出力範囲を広げます。放射と回転では、ずらした色が描かれる範囲を求め、さらに2pxを足した範囲まで広げます。どの色も描かれなかった画素は透明です。

赤、緑、青の各成分には、波長ごとに違う重みを掛けます。そのため、映像の縁や半透明の部分では、成分ごとに映像が覆う割合が違います。不透明度は、そのうち最も大きい割合になります。輪郭の外側には、赤、緑、青の一部だけが届いた縁ができ、元の色にその成分が少ないと、縁は暗く見えます。

## 制限事項

- AviUtl向けのEXO出力には対応していません。
- Direct2Dのカスタムエフェクトを作成できない場合は、エフェクトを適用せず入力映像を表示します。
- 色のずれの計算には現在のフレームの色と不透明度だけを使用します。履歴フレーム、外部画像、学習済みモデルは使用しません。
- 映像の赤、緑、青の3つの値から色を作り直します。映像に含まれない波長の情報を取り出す機能はありません。
- 等色関数は、論文の式(4)の近似式で求めています。CIEの数表との差は、400nmから700nmまでの範囲で、ピーク値の約1.3%以内です。
- 色を混ぜる計算は、映像の値をそのまま使います。ガンマ補正を取り除く変換はしません。
- 放射では、各点の動きの上限が、その点の中心からの距離の半分です。「距離」がそれを超えても、それ以上は動きません。
- 色をずらした映像は元の外形の外へ出るため、出力範囲は元の映像より大きくなります。

## 注意事項

- 処理負荷: 画素ごとの映像の読み取りは「ステップ数」に応じて増えるため、ステップ数が多いほど処理は重くなります。Intel Iris Xe Graphicsで、1920×1080の映像に既定の設定を使い、描画のGPU時間を8回測りました。1回の値は、1.5秒の暖機のあとの240フレームの最小で、既定のステップ数では3.3〜5.8ms、「ステップ数」を64にすると6.0〜10.2msでした。
- 強さ0%と距離0px: 強さが0%のときと、距離が0pxのときは、映像の色を変更しません。
- 再現性: 結果は設定と画素の位置だけから決まります。時間値と乱数は使いません。同じフレームは何度描いても同じ結果になります。
- 透明部分: 色をずらした映像は元の外形の外へはみ出すため、出力範囲は元の映像より大きくなります。赤、緑、青の成分ごとに映像が覆う割合が違うため、輪郭の外側には一部の成分だけが届いた縁ができ、元の色にその成分が少ないと縁は暗く見えます。不透明度は、成分ごとの割合のうち最も大きいものです。
- 更新通知: エフェクトを最初に生成したときに、YMM4の実行中に一度だけ新しい正式版を確認します。更新情報を取得できない場合は通知せず、そのまま動作します。プレリリースは通知の対象に含めません。
- 不具合の自動送信: 想定していない例外が起きたときは、その内容を開発者へ自動で送信します。内容は「不具合の報告」に書いています。
- 本プラグインを使用する前に、YMM4のプロジェクトファイルのバックアップを作成することを推奨します。

## 不具合の報告

本プラグインは、想定していない例外が起きたときに、その内容を開発者へ自動で送信します。同意は求めず、常に送信します。

送信する情報は次のとおりです。

| 種類 | 内容 |
|---|---|
| 例外 | 型の完全名、メッセージ、スタックトレース |
| 発生位置 | モジュール名、関数名、ファイル名、行番号 |
| プラグイン | アセンブリ名、バージョン |
| 実行環境 | OSの名前とバージョン、.NETのバージョン、CPUのアーキテクチャ、論理プロセッサ数 |
| 識別子 | YMM4の起動ごとに決まるセッション識別子、報告ごとの識別子 |

メッセージとファイル名は、送信の前に置き換えを通します。置き換えるのは、Windowsのユーザー名、ユーザーフォルダー、AppDataのパス、マシン名、ドメイン名、メールアドレス、IPv4アドレスです。送信元のIPアドレスは受信側へ渡す手前で取り除いています。

映像の中身とプロジェクトの内容は送信しません。継続して個人を追跡する識別子も持ちません。セッション識別子はYMM4を起動し直すと別の値になります。

送信するのは想定していない例外だけです。YMM4が本プラグインのエフェクトを作るとき、フレームごとに更新するとき、破棄するときと、Direct2Dがシェーダーの定数を書き込むときに起きた例外を報告し、その後はYMM4へそのまま渡します。更新の確認では、更新情報の取得と比較で起きた例外は報告しません。通知の文を組み立てて表示するときに起きた例外は報告し、YMM4へは渡しません。画面の操作やバックグラウンドの処理で未処理になった例外も報告しますが、本プラグインのコードが関わる例外に限ります。本プラグインの外で起きた例外は送信しません。

次の失敗は送信しません。

| 種類 | 例 |
|---|---|
| 効果をかけないだけで済ませるもの | Direct2Dのカスタムエフェクトを作成できないときに、エフェクトを適用せず入力映像を表示したとき |
| 更新の確認の通信の失敗 | manjubox.netとGitHubのどちらへも接続できない |

送信できなかった報告はYMM4のユーザーフォルダーへ退避します。次にYMM4を起動したあと、本プラグインのエフェクトを生成するか、同じくYMM4-Telemetryで報告する別のプラグインが動き始めると、退避した報告を1回の起動で10件まで送り直します。送信も再送も非同期に行うため、通信を待って起動と描画が遅くなることはありません。

実装は [YMM4-Telemetry](https://github.com/routersys/YMM4-Telemetry) をサブモジュールとして取り込んでいます。
