# 色ずれ（スペクトラム） for YMM4

[![License](https://img.shields.io/badge/license-MIT-blue.svg)](#)
[![.NET](https://img.shields.io/badge/.NET-10.0-purple.svg)](#)
[![Release](https://img.shields.io/github/v/release/routersys/YMM4-SpectrumColorShift.svg)](https://github.com/routersys/YMM4-SpectrumColorShift/releases)

---

YukkuriMovieMaker4（YMM4）上で動作する、映像の色を波長に応じてずらし、虹色の縁を作る映像エフェクトプラグインです。
映像の色を 400nm から 700nm の波長に分け、波長ごとに異なる量だけ映像をずらして重ね合わせます。
赤、緑、青の 3 枚を重ねる方式と違い、色が波長に沿って連続して分かれるため、プリズムや回折格子を通したような縁になります。ずらす向きは、直線、放射、回転の 3 方式から選べます。

![Image](https://github.com/routersys/YMM4-SpectrumColorShift/blob/main/docs/SpectrumColorShift.png)

左上が元の映像です。ほかの 3 つは「距離」を 24px にして方式だけを変えた例で、ほかの項目は既定値です。

## 概要

本プラグインは YMM4 の映像エフェクトとして動作します。エフェクトの一覧の「加工」に「色ずれ（スペクトラム）」として表示されます。波長は光の色を表す値で、短いほど青く、長いほど赤くなります。400nm から 700nm までの波長の並びが、スペクトルです。映像の各画素について、波長ごとにずらした位置の色を読み取り、波長ごとの重みを掛けて足し合わせた色で描き直します。重みは、人の目が各波長の光をどんな色として感じるかを表す等色関数から求めます。等色関数の計算は、Wyman、Sloan、Shirley の論文「Simple Analytic Approximations to the CIE XYZ Color Matching Functions」（Journal of Computer Graphics Techniques 2013）に基づきます。

結果は設定と画素の位置だけから決まります。同じフレームは何度描いても同じ結果になります。

処理はピクセルシェーダーで行い、GPU で描画します。設定はアイテムのエフェクトの項目としてプロジェクトに保存します。プラグイン自体の設定ファイルはありません。

画面の表示は日本語のほか、英語、簡体字と繁体字の中国語、韓国語、スペイン語、アラビア語、インドネシア語に対応します。

## インストール方法

1. [Releases](https://github.com/routersys/YMM4-SpectrumColorShift/releases/latest) ページから最新のプラグインファイル（`.ymme`）をダウンロードしてください。
2. YMM4 が起動していないことを確認し、ダウンロードしたファイルを実行してインストールします。
3. YMM4 を起動し、アイテムの映像エフェクトから「加工」の「色ずれ（スペクトラム）」を追加します。
4. 既定の設定では、スペクトルの両端が 8px 動き、青い側が右へ、赤い側が左へずれます。「距離」と「方式」で見た目を調整します。レンズの色収差のような見た目にするには、「方式」を「放射」にして「距離」を数 px にします。

## 主な機能

### 1. 距離と方式

「距離」は、色が動く最大の大きさです。400nm と 700nm の両端のうち、動きが大きいほうの端が、ちょうど「距離」だけ動きます。基準波長は、位置が動かない色の波長です。基準波長より波長の短い側と長い側は、反対の向きへ動きます。0px にすると映像をそのまま通し、負の値にすると向きが逆になります。

「方式」は、ずらす向きの決め方です。

- 直線: 「角度」で決めた一方向へずらします。0° が右、90° が下です。「距離」は映像全体で同じです。
- 放射: 中心から外へ向かってずらします。レンズの色収差に近い見た目になります。ずれは中心からの距離に比例します。「距離」が、中心から最も遠い点までの距離の半分以下のときは、その点で「距離」と等しくなります。青い側は外へ、赤い側は内へずれます。
- 回転: 中心を軸に、波長ごとに異なる角度で回します。中心から最も遠い点が円弧に沿って動く距離が「距離」と等しくなります。青い側は時計回りに、赤い側は反時計回りに回ります。

放射と回転の中心は、画面の中心ではなく、このエフェクトに入る映像の中心です。「中心X」と「中心Y」で、この中心を動かせます。「角度」は方式が直線のときだけ、「中心X」と「中心Y」は方式が放射か回転のときだけ表示されます。

「強さ」は、色をずらした映像を元の映像に混ぜる割合です。0% にすると元の映像のままになります。

### 2. スペクトル

各波長の重みは、等色関数から求めた、その波長の光の赤、緑、青の成分です。負になる成分は 0 にします。さらに、赤、緑、青のそれぞれで、すべての波長の重みを足すと 1 になるよう揃えます。このため、「距離」が 0px のときと、色が一様な領域では、映像の色は変わりません。

「基準波長」は、位置が動かない色の波長で、範囲は 400nm から 700nm までです。450nm 付近が青、550nm 付近が緑、650nm 付近が赤です。450nm にすると青が動かず、緑と赤が青から離れる向きへ動きます。

「分散」は、波長ごとの動きの大きさをどう決めるかを選ぶ項目です。

- 回折格子: 回折格子は、細かい溝で光を波長ごとに分ける板です。この方式では、動きが、波長と基準波長との差に比例し、スペクトルが均等に広がります。
- プリズム: プリズムは、光を屈折させて波長ごとに分けるガラスなどの透明な塊です。この方式では、動きが、波長の 2 乗の逆数と基準波長の 2 乗の逆数との差に比例し、青い側が大きく広がり、赤い側は狭くなります。この式は、ガラスの屈折率が波長によって変わる様子を表すコーシーの分散式の、主な項と同じ形です。

「ステップ数」は、400nm から 700nm までを等間隔に分ける波長の数です。画素ごとに、この数に応じた回数だけ映像を読み取ります。「距離」が大きいと、ステップ数が少ないときに、色ごとの映像が離れて段のように見えます。回折格子では、「距離」の 2 倍を「ステップ数」から 1 を引いた数で割った値が、隣り合う波長の動きの差の上限です。プリズムでは、青い側の差がこの値より大きくなります。この差が小さいほど、色はなめらかにつながります。ステップ数を増やすほど処理は重くなります。

### 3. 映像の外形

色をずらした映像は、元の外形の外へはみ出します。直線では、「角度」で決めた向きに沿って「距離」を横の長さと縦の長さに分け、その長さをそれぞれ切り上げて 2px を足した幅だけ、出力範囲を広げます。放射と回転では、ずらした色が描かれる範囲を求め、さらに 2px を足した範囲まで広げます。どの色も描かれなかった画素は透明です。

赤、緑、青の各成分には、波長ごとに違う重みを掛けます。そのため、映像の縁や半透明の部分では、成分ごとに映像が覆う割合が違います。不透明度は、そのうち最も大きい割合になります。輪郭の外側には、赤、緑、青の一部だけが届いた縁ができ、元の色にその成分が少ないと、縁は暗く見えます。

## パラメータ一覧

| 項目 | 既定値 | 内容 |
|---|---|---|
| 距離 | 8px | 色が動く最大の大きさです。-4096px から 4096px までで、スライダーでは -100px から 100px までです。0px にすると映像をそのまま通し、負の値にすると向きが逆になります。 |
| 方式 | 直線 | ずらす向きの決め方です。直線、放射、回転から選びます。 |
| 角度 | 0° | 基準波長より波長の短い側が動く向きです。0° が右、90° が下です。-100000° から 100000° までで、スライダーでは -360° から 360° までです。方式が直線のときに表示します。 |
| 中心X | 0px | 中心を映像の中心から横へ動かす距離です。右が正です。-4096px から 4096px までで、スライダーでは -500px から 500px までです。方式が放射か回転のときに表示します。 |
| 中心Y | 0px | 中心を映像の中心から縦へ動かす距離です。下が正です。範囲は「中心X」と同じです。方式が放射か回転のときに表示します。 |
| 強さ | 100% | 色をずらした映像を元の映像に混ぜる割合です。0% から 100% までで、0% にすると映像をそのまま通します。 |
| 分散 | 回折格子 | 波長ごとの動きの大きさの決め方です。回折格子かプリズムから選びます。 |
| 基準波長 | 550nm | 位置が動かない色の波長です。400nm から 700nm までです。 |
| ステップ数 | 32 | 400nm から 700nm までを分ける波長の数です。8 から 64 までの整数です。 |

「距離」から「強さ」までは「色ずれ」、「分散」から「ステップ数」までは「スペクトル」のグループにあります。「方式」「分散」「ステップ数」はアニメーションできません。ほかの 6 項目は、YMM4 のアニメーションの設定で時間に沿って変えられます。

## 制限事項

- 映像の赤、緑、青の 3 つの値から色を作り直します。映像に含まれない波長の情報を取り出す機能はありません。
- 等色関数は、論文の式 (4) の近似式で求めています。CIE の数表との差は、400nm から 700nm までの範囲で、ピーク値の約 1.3% 以内です。
- 色を混ぜる計算は、映像の値をそのまま使います。ガンマ補正を取り除く変換はしません。
- 放射では、各点の動きの上限が、その点の中心からの距離の半分です。「距離」がそれを超えても、それ以上は動きません。
- 色をずらした映像は元の外形の外へ出るため、出力範囲は元の映像より大きくなります。
- AviUtl の exo ファイルへの書き出しには対応していません。

## 注意事項

- 処理の重さ: 画素ごとの映像の読み取りは「ステップ数」に応じて増えるため、ステップ数が多いほど処理は重くなります。Intel Iris Xe Graphics で、1920×1080 の映像に既定の設定を使い、描画の GPU 時間を 3 回測りました。1 回の値は 60 フレームの最小で、既定のステップ数では 5.6〜8.4ms、「ステップ数」を 64 にすると 12.6〜15.7ms でした。
- 更新の確認: アイテムに色ずれ（スペクトラム）を追加するか、色ずれ（スペクトラム）を含むプロジェクトを開いたときに、YMM4 の起動ごとに一度だけ GitHub のリリースを確認し、新しいものがあればメッセージで知らせます。
- 不具合の自動送信: 想定していない例外が起きたときは、その内容を開発者へ自動で送信します。内容は「不具合の報告」に書いています。
- 本プラグインを使用する前に、YMM4 プロジェクトファイルのバックアップを作成することを推奨します。

## 不具合の報告

本プラグインは、想定していない例外が起きたときに、その内容を開発者へ自動で送信します。同意は求めず、常に送信します。

送信する情報は次のとおりです。

| 種類 | 内容 |
|---|---|
| 例外 | 型の完全名、メッセージ、スタックトレース |
| 発生位置 | モジュール名、関数名、ファイル名、行番号 |
| プラグイン | アセンブリ名、バージョン |
| 実行環境 | OS の名前とバージョン、.NET のバージョン、CPU のアーキテクチャ、論理プロセッサ数 |
| 識別子 | YMM4 の起動ごとに決まるセッション識別子、報告ごとの識別子 |

メッセージとファイル名は、送信の前に置き換えを通します。置き換えるのは、Windows のユーザー名、ユーザーフォルダー、AppData のパス、マシン名、ドメイン名、メールアドレス、IPv4 アドレスです。送信元の IP アドレスは受信側へ渡す手前で取り除いています。

映像の中身とプロジェクトの内容は送信しません。継続して個人を追跡する識別子も持ちません。セッション識別子は YMM4 を起動し直すと別の値になります。

送信するのは想定していない例外だけです。YMM4 が本プラグインのエフェクトを作るとき、フレームごとに更新するとき、破棄するときと、Direct2D がシェーダーの定数を書き込むときに起きた例外を報告し、その後は YMM4 へそのまま渡します。画面の操作やバックグラウンドの処理で未処理になった例外も報告しますが、本プラグインのコードが関わる例外に限ります。本プラグインの外で起きた例外は送信しません。

次の失敗は送信しません。

| 種類 | 例 |
|---|---|
| 効果をかけないだけで済ませるもの | Direct2D がエフェクトを作れず、映像をそのまま通したとき |
| 更新の確認の通信の失敗 | GitHub へ接続できない |

送信できなかった報告は YMM4 のユーザーフォルダーへ退避し、次回の起動時に送り直します。送信も再送も非同期に行うため、起動と描画が遅くなることはありません。

実装は [YMM4-Telemetry](https://github.com/routersys/YMM4-Telemetry) をサブモジュールとして取り込んでいます。
